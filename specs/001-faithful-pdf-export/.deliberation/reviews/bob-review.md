# Bob review — faithful-pdf-export

## 1. What problem is this actually solving?

Teachers edit manuals at /manuals and the downloaded PDF does not reflect their edits. On mapped slugs the download serves a static 2022 file; on unmapped slugs it falls through to a lossy renderer that loses the editorial rhythm. One delivery path, two failure modes, both visible to the teacher who just edited. The fix is one runtime path that reads current blocks and prints them faithfully, with the static PDFs kept as a fallback.

## 2. Smallest first version that proves the idea

M1 is a working English render for one slug behind a feature flag. Demoable surface: `/manuals/rose-meditation-level-1/print?lang=en` renders the print page from live Supabase blocks, and `/api/manuals/rose-meditation-level-1/pdf?lang=en` returns a PDF generated by Puppeteer on Vercel. The Download menu is unchanged, the static fallback at `public/manuals/pdf/` is unchanged. Jennifer clicks one URL, gets a PDF that reflects her last edit. That is the proof. Everything after that is breadth.

## 3. Three risks that would kill this if ignored

- **Chromium-on-Vercel wired late.** If M1 ships the print page first and the Puppeteer route second, M1 looks done in local dev and dies on Vercel. The chromium decision must land in M1, not M2. Otherwise M2 ships before M1 is firm and the whole thing has to be re-platformed.
- **Print template grouping rules pinned only to English.** If the panel-grouping heuristic is tuned against `Rose-Level-1-Manual-EN.pdf` and then language fan-out happens, the pt/es/el/ru/uk renders will surface rhythm bugs that English never showed. Locking the heuristic before multi-language proofing doubles the work.
- **Fallback chain undefined.** If the runtime route fails on Vercel, the Download menu must degrade to the static PDF or to the lossy HTML path silently. If that chain is left until last, teachers will hit blank downloads in production while the team debugs chromium binaries.

## 4. What success looks like at 90 days

All six languages of the three rose-meditation slugs render through the runtime route on Vercel. aura-level-1 also renders. Teachers' edits are visible in the next download within seconds. The static-PDF fallback has been invoked fewer than five times in the trailing 30 days, observed via Sentry. No open issue in Light-Brands/roses-os is labeled `pdf-export`. `pdf-map.ts` still exists as the fallback registry, not as the primary path.

## 6. The one thing only the sequencer would notice

Issue #504 (language re-sync) is named out-of-scope, but M3 cannot demo cleanly while pt/es/el/ru/uk blocks are stale snapshots from before covers and TOC. The render is faithful to the blocks, the blocks are not faithful to the source. Without sequencing M3 acceptance to "rhythm and typography only, not content parity," #504 silently moves into this spec and M3 stops shipping. Name that boundary in the M3 ACs before M2 lands or M3 gets stuck.
