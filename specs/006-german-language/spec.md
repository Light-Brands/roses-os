# Spec 006 — German language for the manuals

## Problem

Roses OS (International Aura and Dream School) ships its manuals in six languages:
`en, pt, es, el, ru, uk`. The school needs a seventh: German (`de`, "Deutsch").
"The manuals" is three distinct product surfaces that each carry their own
language switch, so German is only honest when it exists behind all three:

1. The block-based manual editor / reader (`/manuals/<id>`), whose content is
   per-language rows in the Supabase `manual_blocks` table.
2. The teaching pages (`/teaching/level-N`), whose text is `src/content/teaching/<locale>.json`.
3. The downloadable PDFs (`public/resources/manuals/*.pdf`) — both the designed
   student manuals and the live in-app export.

Adding `de` to the switcher without the content behind it would show an empty
editor and 404 the German PDFs. So the code and the content are one arc.

German content is machine-translated (Gemini) from the corrected English as a
starting point, exactly as `el/ru/uk` were, and reviewed by a German-fluent
member of the team before it goes live on prod.

## Whole-problem surface

```yaml
- id: S1-lang-registry
  surface: The de language code is a first-class member of every language enum, switcher, and validator (manuals editor, teaching i18n, persisted-locale whitelist)
  covers-milestone: M1
- id: S2-pdf-wiring
  surface: German is wired into the per-locale PDF path/label config and the designed-PDF map so the download buttons resolve DE files and the live export tags DE
  covers-milestone: M1
- id: S3-teaching-content
  surface: The /teaching pages render fully in German (src/content/teaching/de.json exists with key-parity to en.json and loads via the dynamic import)
  covers-milestone: M2
- id: S4-manual-blocks
  surface: The manual editor/reader serves German rows for every manual (L1, L2, L3, aura-level-1) staged from the English source via the MT pipeline
  covers-milestone: M3
- id: S5-designed-pdfs
  surface: German designed student-manual PDFs (Rose-Level-1/2/3-Manual-DE.pdf) exist and render, matching the ES/PT/RU/UK production pipeline
  covers-milestone: M4
- id: S6-teachers-aid-pdf
  surface: The German Teachers-Aid PDF (ROSES-OS-Teachers-Aid-DE.pdf) exists, generated by the same downscaled-image pipeline the other Teachers-Aid PDFs use
  covers-milestone: M4
- id: S7-native-review
  surface: A German-fluent reviewer passes the generated German content before prod promotion; only reviewer-approved content is promoted
  covers-milestone: M5
```

## Acceptance criteria

- AC1: `ManualLanguage` and `MANUAL_LANGUAGES` in `src/lib/manuals/types.ts` include `de` with label "Deutsch", so the editor language switch renders a German option.
- AC2: `Locale` and `LOCALES` in `src/lib/i18n/types.ts` include `de` with label "Deutsch", and the persisted-locale whitelist in `src/lib/i18n/context.tsx` accepts `de`.
- AC3: `manualPdfConfigs` (L1, L2, L3) and `teachersAidPdfConfig` in `src/lib/data/manual-pdf-paths.ts` carry `de` paths and a German label builder; `LANG_CODE` in `src/lib/manuals/pdf-map.ts` maps `de` to `DE`.
- AC4: `src/content/teaching/de.json` exists, is valid JSON, and has the exact key structure of `en.json` (deep key-parity, zero missing or extra keys).
- AC5: The teaching pages load German without falling back: `/teaching/level-1` under locale `de` renders German chrome, not the previous language.
- AC6: The Supabase `manual_blocks` staging lanes carry German rows for L1, L2, L3, and aura-level-1, count-matched to the English source per manual, with real German text (zero residual-English on headings), image `src` untouched. The German strings are produced by `scripts/translate-mt.ts` and written to the lanes by `scripts/stage-translation.ts`.
- AC7: `Rose-Level-1-Manual-DE.pdf`, `Rose-Level-2-Manual-DE.pdf`, `Rose-Level-3-Manual-DE.pdf` exist under `public/resources/manuals/`, render with no broken images, and match the layout of the ES/PT designed PDFs.
- AC8: `ROSES-OS-Teachers-Aid-DE.pdf` exists under `public/resources/manuals/` and renders with the new-name branding and no broken images. (External-blockable per the 96MB image-weight wall on this Windows box.)
- AC9: A German-fluent reviewer reviews the generated German (teaching JSON + a sample of manual blocks + the PDFs) and returns pass/fix findings before any prod promotion.
- AC10: `tsc --noEmit` shows no new errors on the changed files; the pipeline scripts (`generate-translated-student-manuals.ts`, `generate-translated-teachers-aid.ts`, `build-manual-translation-maps.mjs`, `import-manuals-to-blocks.ts`) carry `de`.

## Out of scope

- Human-refined final German copy. The generated German is the starting point the
  teachers refine in the editor, the same posture as every non-English language.
  **Why external:** external: named-human-signoff — final teacher refinement is
  authored by the school's German teachers, tracked as ongoing editor work, not a
  code deliverable.
- Backfilling German into any manual whose English source is itself incomplete
  beyond what the current reconstruction covers.
